# Progress / Roadmap

Where the port stands. [STATUS.md](STATUS.md) has the full history of how
each piece was found and fixed.

The goal is the original game, running natively: fixes are limited to what
the PC port needs (timing, rendering and runtime differences from the N64),
and leave the game's own behaviour, look and balance alone.

## Done

- [x] ROM layout: main code segment plus **308 relocatable code overlays**
      (ROM 0xB6BCC0-0xEBDA70), found and checked against the game's own
      overlay descriptors (`tools/overlays.py`)
- [x] Symbol file: 10,829 functions across main and every overlay, with each
      overlay's relocations taken from its own relocation table
      (`YoshiStorySyms/`, regenerated by `tools/regen_symbols.sh`)
- [x] First clean N64Recomp run over the whole game
- [x] Runtime project: CMake, launcher/frontend, ROM picker with hash check,
      EEPROM saves, crash log
- [x] Overlays registered with the runtime as the game loads them
- [x] Audio microcode (RSP) recompiled from the ROM
- [x] First full build: `DinoTale` compiles and links (Linux)

- [x] **First boot: title screen and the storybook intro render**
      (Linux, software renderer; round 3)

## Where things are

| Path | What |
|---|---|
| `yoshisstory.us.toml` | N64Recomp config |
| `YoshiStorySyms/` | Symbol file: function boundaries and overlay relocations |
| `tools/overlays.py` | Finds the overlays and parses their relocation tables |
| `tools/gen_overlay_yaml.py` | splat segments for the overlays |
| `tools/make_syms.py` | Builds the symbol file |
| `tools/regen_symbols.sh` | The whole symbol pipeline, from your ROM |
| `tools/normalize_rom.py` | Converts `.n64`/`.v64` dumps to `.z64` |
| `aspMain.us.toml` | RSPRecomp config for the audio microcode |
| `src/main/` | Frontend: window, audio, input, config, crash reporting |
| `src/game/` | Game-specific runtime pieces |
